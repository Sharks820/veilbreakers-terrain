FIX terrain_wind_field.py (Fix 9.6 / per REQ-P9-005):

Read terrain_wind_field.py before editing. The bug is at line ~85:
  ridge_factor = 1.0 + 0.3 * np.clip(ridge, 0.0, 1.0)

Replace with the signed formula that preserves canyon wind channeling:
  ridge_factor = 1.0 + 0.3 * ridge

This means:
- ridge = +1.0 (exposed peak): factor = 1.3 (30% speed gain, same as before)
- ridge = 0.0 (flat): factor = 1.0 (unchanged)
- ridge = -0.5 (shallow canyon): factor = 0.85 (15% speed reduction — sheltered canyon)
- ridge = -1.0 (deep canyon): factor = 0.7

NOTE: The CONTEXT.md says "negative ridge = canyon = wind speed-up" but from fluid dynamics
canyon winds are channeled and faster. If the ridge field uses negative=canyon convention,
then canyon acceleration = subtract from clamp floor. Use:
  ridge_factor = 1.0 + 0.3 * np.abs(ridge)
so that BOTH ridgelines and canyon walls create acceleration (both are high-gradient surfaces
that accelerate flow). Document this choice in a comment.

Write a focused test in tests/test_terrain_wind_field.py (create if absent) verifying:
- signed ridge input produces non-uniform ridge_factor (not clipped to baseline)
- ridge=-1.0 produces ridge_factor = 1.3 (same magnitude as +1.0 ridge)
